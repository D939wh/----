# 目录规矩（2026-11-02 定稿，2026-11-04 补数据层与单例，2026-11-06 同步「按编号」架构）

> 一句话：**看名字就知道该往哪放；一个东西一个家。**
> 放不进去，说明目录名字起错了，不是东西太多。
> **这是规矩，不是备忘**——新会话的 AI 开工前先读它，改它之前必须先问用户（2026-11-02 15:46 用户拍板）。

## 核心原则：按「具体什么东西」分，不按「什么类型」分

❌ 错的做法：一个 `界面/` 塞进所有界面，一个 `交互物/` 塞进所有物件。
等界面长出五六个（小地图、倒计时、负重条、危险度环、道具格），`界面/` 就会变成一个谁都能扔东西的筐，打开一看全是文件，改一个怕碰坏另一个。

✅ 对的做法：**每样东西自己一个文件夹**，文件夹名就是那个东西的名字。

```
界面/
├── 道具格/        道具格.tscn + 道具格.gd + 道具格用到的图
├── 倒计时/        （W2 建）
├── 负重条/        （W3 建）
└── 小地图/        （W3 建）
```

好处：改道具格只开 `道具格/`，不用在一堆文件里找；新增一个界面就是新增一个文件夹，永远不用挤。

## 数据目录放什么（2026-11-04 定稿）

`数据/` 只装**没法被场景副本表达**的东西。它**不放流程判断**——「重量大于 40 就禁止攀爬」这种 if 属于代码，不属这里。

**11-06 起分三层**：根目录只放**规则**（对所有地图生效）；**坐标表按用途进两个文件夹** —— `正式/` 是 `run/main_scene` 那一局用的，`测试/` 是自测当布景的旧图用的。改正式手感不要碰 `测试/`，改测试布景也不要动 `正式/`。

| 文件 | 管什么 | 为什么必须是表 | 现状 |
| --- | --- | --- | --- |
| `重量档位.gd` | 换算规则：80 公斤 → 4 档 → 速度 ×0.3、不能跳、不能爬 | 它不属于任何一件东西，是所有重物共用的一把尺子 | ✅ 在跑 |
| `通用规则.gd` | 开门用时（学生 0.3 / 宿管 1.5）、钥匙板几块、什么颜色 | 它不属于任何一张地图，**每一张图都要用同一份** —— 放进某张图里就等于绑死在那张图上（11-06 就是从一楼那张表里拆出来的） | ✅ 在跑 |
| `正式/物件清单.gd` | 正式那一局（四层图 `主场景2.tscn`）摆了什么：**键=编号**，值=类型+坐标 | 布局。没有哪个单件场景能表达「这张图有几扇门」。**只写编号/类型/坐标，一条规则都不写** | ✅ 在跑（13 条） |
| `测试/物件清单_旧一楼.gd` | 旧一楼图（`主场景.tscn`）摆了什么 | 同上，图换了一份。只给自测当布景 | ✅ 在跑（7 条，测试用） |

**一句话分清**：**地图清单只回答「这张图的东西在哪」；规则一律进 `通用规则.gd`，对所有地图生效。**

| 旧名 | 现在叫 |
| --- | --- |

### 为什么没有「角色库」「道具库」

主人原话：「角色学生他是自我复制的，只要有一个做好的学生，他就可以一直使用——**学生他自己就是一个角色库**。图鉴也是同样道理。」

Godot 的 `.tscn` 本身就是模板：`student.tscn` 做好一个就能复制出无数个，数值写在它自己的脚本上、跟着场景走。再建一张角色库表，等于把同一件事记两遍；两遍必然分叉。

**11-04 建过的 `数据/角色库.gd` 已经删掉了**：它 24 项里 20 项和 `student.gd` 重复、13 项和 `宿管.gd` 重复，而且**零引用、改了不生效**——是一份会骗人的数据。

判断标准一句话：**能在场景副本里自己带着走的，别建表。**

- 学生走多快、跳多高 → 学生脚本里
- 箱子多重、门多宽 → 各自的场景/脚本里
- 这张图有几个门、在哪 → 物件清单
- 多重算几档、罚多少 → 重量档位

**什么时候该反过来建表**（现在三条都不满足）：同类东西多到要横向比较（比如 30 件道具平衡数值）、需要程序随机生成（刷宝箱）、联机要主机下发数值。

### 开门属于场景，不属于人（11-04 定）

主人原话：「开门应该属于场景内容，属于场景的数据，角色向场景发送数据。」

所以：**角色只说一句「我要推这扇门」，句子说完就没它的事了。**

```
角色 ──"我要推你"──▶ 门 ──查清单──▶ 自己按 0.3 / 1.5 秒开
					│
					└─ 开够了自己撤掉拦路的碰撞体 ──▶ 人撞过去就过去了
```

「场景回馈」不需要是一句话：**碰撞体消失就是回馈，而且是玩家用眼睛看得见的那种**。让角色再收一份「本次耗时 1.5 秒」的字典，等于给自己存一个没人读的变量——能删就删。

时长住在 `数据/通用规则.gd`（全工程默认），某扇门想特殊就写在那张图的清单里：

```gdscript
# 数据/通用规则.gd —— 全楼默认，对所有地图生效
const 默认开门用时 := { "求生者": 0.3, "宿管": 1.5 }

# 数据/正式/物件清单.gd —— 这张图摆了什么；某一个例外写在这一条里
const 物件 := {
	"1-走廊东": { "类型": "门", "位置": Vector2(968, 464) },      # 用默认 0.3 / 1.5
	"1-防火门": { "类型": "门", "位置": Vector2(1200, 464),       # 单独配
				  "开门用时": { "求生者": 3.0, "宿管": 3.0 } },
}
```

只写了谁，谁才变；没写的那个继续用默认。`门.gd`、`student.gd`、`宿管.gd` 一个字都不用改。

## 四条硬规矩

**① 一个东西一个文件夹，文件夹名 = 东西的名字。**
不要建「杂项」「其他」「临时」「通用」这类筐。

**② 脚本必须和它的场景在同一个文件夹。**
`角色/学生/student.tscn` 旁边的 `student.gd` 就是它的脚本。改一个东西不用跳两个目录。

**③ 素材目录只放原料，不放能跑的 .tscn。**
`素材/` 清空重导不该损失任何功能。一旦有场景住进去，清空就等于删功能。

**④ 测试场景一律进 `场景/测试/`。**
正式要交付的和临时验证的必须一眼分得开。
