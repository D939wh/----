# 目录规矩（2026-11-02 定稿，2026-11-04 补上数据层与单例）

> 一句话：**看名字就知道该往哪放；一个东西一个家。**
> 放不进去，说明目录名字起错了，不是东西太多。
> **这是规矩，不是备忘**——新会话的 AI 开工前先读它，改它之前必须先问用户（2026-11-02 15:46 用户拍板）。

## 核心原则：按「具体什么东西」分，不按「什么类型」分

❌ 错的做法：一个 `界面/` 塞进所有界面，一个 `交互物/` 塞进所有物件。
等界面长出五六个（小地图、倒计时、负重条、危险度环、道具格），`界面/` 就会变成一个谁都能扔东西的筐，打开一看全是文件，改一个怕碰坏另一个。

✅ 对的做法：**每样东西自己一个文件夹**，文件夹名就是那个东西的名字。

```
界面/
├── 道具格/        道具格.tscn + 道具格.gd + 道具格用到的图
├── 倒计时/        （W2 建）
├── 负重条/        （W3 建）
└── 小地图/        （W3 建）
```

好处：改道具格只开 `道具格/`，不用在一堆文件里找；新增一个界面就是新增一个文件夹，永远不用挤。

## 数据目录放什么（2026-11-04 定稿）

`数据/` 只装**没法被场景副本表达**的东西。它**不放流程判断**——「重量大于 40 就禁止攀爬」这种 if 属于代码，不属这里。

| 文件 | 管什么 | 为什么必须是表 | 现状 |
| --- | --- | --- | --- |
| `重量档位.gd` | 换算规则：80 公斤 → 4 档 → 速度 ×0.3、不能跳、不能爬 | 它不属于任何一件东西，是所有重物共用的一把尺子 | ✅ 在跑 |
| `楼层清单.gd` | 摆位：一层楼有哪些门、在哪个坐标 | 布局。没有哪个单件场景能表达「这一层有几扇门」 | ✅ 在跑 |

### 为什么没有「角色库」「道具库」

主人原话：「角色学生他是自我复制的，只要有一个做好的学生，他就可以一直使用——**学生他自己就是一个角色库**。图鉴也是同样道理。」

Godot 的 `.tscn` 本身就是模板：`student.tscn` 做好一个就能复制出无数个，数值写在它自己的脚本上、跟着场景走。再建一张角色库表，等于把同一件事记两遍；两遍必然分叉。

**11-04 建过的 `数据/角色库.gd` 已经删掉了**：它 24 项里 20 项和 `student.gd` 重复、13 项和 `宿管.gd` 重复，而且**零引用、改了不生效**——是一份会骗人的数据。

判断标准一句话：**能在场景副本里自己带着走的，别建表。**

- 学生走多快、跳多高 → 学生脚本里
- 箱子多重、门多宽 → 各自的场景/脚本里
- 某层有几个门、在哪 → 楼层清单
- 多重算几档、罚多少 → 重量档位

**什么时候该反过来建表**（现在三条都不满足）：同类东西多到要横向比较（比如 30 件道具平衡数值）、需要程序随机生成（刷宝箱）、联机要主机下发数值。

**还有一处没搬完**：开门时间（学生 0.3 / 宿管 1.5）现在写在 `门.gd` 里。按上面这条，它属于「人」，该搬进学生、宿管各自的脚本，门每次问推它的人一句「你要几秒」。现状是门替所有人定了速度。

## 四条硬规矩

**① 一个东西一个文件夹，文件夹名 = 东西的名字。**
不要建「杂项」「其他」「临时」「通用」这类筐。

**② 脚本必须和它的场景在同一个文件夹。**
`角色/学生/student.tscn` 旁边的 `student.gd` 就是它的脚本。改一个东西不用跳两个目录。

**③ 素材目录只放原料，不放能跑的 .tscn。**
`素材/` 清空重导不该损失任何功能。一旦有场景住进去，清空就等于删功能。

**④ 测试场景一律进 `场景/测试/`。**
正式要交付的和临时验证的必须一眼分得开。

## 文件夹颜色（一进编辑器就知道哪是哪）

在「项目 → 项目设置 → 文件自定义」里配，也可以直接改 `project.godot` 的 `folder_colors`。当前方案：

| 目录 | 颜色 | 意思 |
| --- | --- | --- |
| `场景/` | 黄 | 能 F5 跑的成品 |
| `场景/测试/` | 青 | 临时验证，可删 |
| `场景/楼层代理/` | 青 | 每层一个的管家（逻辑） |
| `单例/` | 绿 | 全局唯一的那一个（跨项目固定：单例=绿） |
| `数据/` | 琥珀 | 纯数据清单，改它不用改代码 |
| `角色/` | 橙 | 会动的实体 |
| `角色/学生/` | 黄 | 主角 |
| `角色/宿管/` | 紫 | 敌人（跨项目固定：敌人=紫） |
| `交互物/` | 蓝 | 地图里拖进去就能用的东西 |
| `交互物/门/` | 蓝 | 一扇门（场景 + 脚本 + 它自己的图） |
| `界面/` | 粉 | 屏幕上的 UI（跨项目固定：界面=粉） |
| `素材/` | 红 | 原料图（跨项目固定：美术=红） |
| `参考资料/` | 灰 | 不参与运行 |
| `调试工具/` | 灰 | 工具 |

**踩过的坑（2026-11-02）**：目录改名后，`folder_colors` 里还写着旧目录名，5 个颜色全部失效——打开编辑器一片白。**以后任何一次目录改名，必须同步改这里**，改完用脚本核一遍「每个颜色键对应的目录是否真实存在」。

## 以后加新东西怎么放（对照表）

| 你要加的东西 | 放哪 |
| --- | --- |
| 宿管角色 | `角色/宿管/` |
| 2 楼地图 | `场景/二楼/` |
| 门 / 电闸箱 / 快递柜 | `交互物/门/`、`交互物/电闸箱/`… 各自一个文件夹 |
| 小地图 / 倒计时 / 负重条 | `界面/小地图/`、`界面/倒计时/`… 各自一个文件夹 |
| 新画的图块 | `素材/场景/图块/` |
| 新道具的图 | `素材/道具/<道具名>/` |
| 用完就删的验证场景 | `场景/测试/` |
| 通用组件（状态机、负重） | `组件/<组件名>/`（W3 用到时再建，现在建了也是空的） |
| 全局管线（总管） | `单例/场景总管.gd`，autoload 名 `Director`，全局只此一个 |
| 某层有什么东西 | `数据/楼层清单.gd`，加门/灯只改这张表 |
| 新楼层的管家 | `场景/楼层代理/` 挂 `楼层代理.gd`，把 `floor_id` 改成那层的名字 |
