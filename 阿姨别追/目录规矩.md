# 目录规矩（2026-11-02 重排后定稿）

> 一句话：**看名字就知道该往哪放**。放不进去，说明这个目录的名字起错了，不是东西多。

## 七个顶层目录，各管一件事

| 目录 | 放什么 | 不放什么 |
| --- | --- | --- |
| `场景/` | 能 F5 直接跑的东西：主场景、各楼层、菜单 | 素材图、脚本 |
| `场景/测试/` | 临时验证用的场景，验收完可以删 | 正式要交付的场景 |
| `角色/` | 每个角色一个子目录，**脚本和场景挨着放** | 通用组件、UI |
| `交互物/` | 地图里拖进去就能用的东西：梯子、箱子、门、电闸箱 | 角色、界面 |
| `界面/` | HUD、菜单绘制、提示框 | 世界里的物件 |
| `素材/` | **只放原料**：png、tres 配置。可以随时删了重导 | 能跑的 .tscn 场景 |
| `参考资料/` | 教学用的参考答案、笔记。**不参与游戏运行** | 正式代码 |
| `调试工具/` | 验证脚本、生图脚本、批处理 | 游戏内容 |

## 三条硬规矩

**① 脚本挨着场景。**
`角色/学生/student.tscn` 旁边的 `student.gd` 就是它的脚本。改一个角色不用跳两个目录。

理由：脚本是场景的"大脑"，分家之后找东西要记两条路径，还要担心改了这边忘那边。

**② 素材目录里不许放能跑的场景。**
`素材/` 是原料仓库，清空重导不会损失什么。一旦有 .tscn 住进去，清空就等于删功能。

**③ 测试场景一律进 `场景/测试/`。**
正式的东西和临时验证的东西必须一眼分得开，否则交付时不知道该给哪一份。

## 以后加新东西怎么放（举例子）

| 你要加的东西 | 放哪 |
| --- | --- |
| 宿管角色（W2） | `角色/宿管/` |
| 2 楼地图 | `场景/楼层/二楼.tscn` |
| 门、电闸箱、快递柜 | `交互物/` |
| 小地图、倒计时条 | `界面/` |
| 新画的图块、色板 | `素材/场景/` |
| 一个用完就删的验证场景 | `场景/测试/` |
| 通用组件（状态机、负重） | `组件/`（W3 用到时再建，现在建了也是空的） |
