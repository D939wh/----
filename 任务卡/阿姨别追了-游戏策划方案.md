本作是一款 2D 横版侧视的 4v1 非对称对抗游戏：四名大学生在熄灯锁楼之后想溜出宿舍去网吧开黑，而宿管正在楼道里巡逻。他们要穿梭五层宿舍楼，找到 3 块焊着整串钥匙的铁板，扛到 5 座电闸箱中的任意 3 座合闸，让东西两扇门禁断电，再从地图最左或最右的门冲出去；宿管一方要阻止他们。核心差异点不是「修进度条」，而是「背上的重量」——物件分 1 / 2 / 3 / 4 四档（每档 20 公斤），扛起即减速、即爬不了梯子、即发出声响；队友本身也是一件可扛、可抛、可接的货物。

文档给出完整可执行的系统与数值：5 座电闸箱 / 任意 3 座断电 / 单座读条 12 秒、3 块钥匙板 / 6 个候选点、中重量减速 40%、宿管追击 5.4 m/s 对学生 4.6 m/s、跳跃初速 −260 px/s（≈8.1 m/s）、抛投最远 6 米、8 个快递柜格口按时间逐个弹开、左右两扇门。目标胜率锁定在学生 45%–55%、平均逃出 1.6 人，靠「惨胜」而非「碾压」维持情绪张力。（2026-10-30 注：速度类数值以「移动手感细参表」的代码像素值为准，米制换算视口放大后已失真。）

本作不是商业项目，而是阶段性练手产物：目标是把「一个完整游戏从场景树到联机」亲手走一遍——节点与场景的父子层级、基础 GDScript 编写、TileMap 地图设计、角色与 AI 的状态机、信号驱动的解耦通信。因此美术、音频、商业化部分都按「够用就好」写，重点放在系统结构可读懂、可拆改。技术侧采用 Godot 4.7 + 主机权威同步（20 Hz 快照），按六周排期推进：W1 只做移动手感，W3 做搬运与状态机，W4 把全局状态收拢，W5 才碰局域网同步。规模按 1 人 + AI 辅助推进，最大风险是范围失控与跳跃手感。

# 一、项目概述

## 1.1 一句话概念

晚上十一点半，宿舍楼熄灯、锁门、电子门禁咔哒一声扣死，四个大学生却早就约好了去网吧开黑。宿管把整串钥匙焊在一块铁板上锁进了值班室，而门禁只认电——他们只能左右奔跑、跳跃攀爬，把散落在各楼层、重达几十斤的钥匙板扛到五座电闸箱前，一座一座合闸。而搬起来的每一样东西，都让他们变慢、变响、变成活靶。他们可以扛起、扔出甚至用接力传递自己的室友。合闸任意三座之后，宿舍楼东西两端的门禁同时断电弹开，谁能跑到其中一边，谁今晚就能上线。而今晚值班的那位宿管，正拿着手电在楼道里等着他们。

## 1.3 设计支柱

三条支柱决定所有取舍，任何与支柱冲突的设计一律砍掉。

### 支柱一：信息不对称才是紧张的来源

宿管掌握楼道结构与声响信息，学生掌握钥匙板位置与合闸进度。双方永远只知道一半真相，紧张感来自「她知道我在哪，我不知道她在哪」。

### 支柱二：所有重物都得用身体去搬，重量就是代价

本作没有任何「隔空拾取」：钥匙板、道具、纸箱、蹲在地上的队友，全都得扛在身上。1 到 4 档、每档 20 公斤的重量分级，分别决定你还能不能跑、能不能跳、能不能爬梯子——每一次搬运都是一次当众下注，赌注是位置和时间。

### 支柱三：多电闸箱与两扇门，逼出分兵与取舍

不设唯一目标点：五座电闸箱分散在不同楼层，合闸任意三座即可让东西两扇门断电。队伍必须决定「保哪几座、放弃哪几座、谁去东门、谁去西门」；宿管也永远不可能守住全部。每个阶段都强制双方做出选择，避免出现「双方互相找不到、原地绕圈」的空转局。

| 同学 / 好友 | 帮忙开 4 人局做联机测试        | 不用教就能上手，能给出手感与规则的直观反馈         |

## 1.5 设计亮点（相对同类作品）

像素皮 + 追逃骨：2D 像素风把美术成本压到最低，把预算和注意力全投到「光」上——走廊感应灯、手电光柱、熄灯后的全黑楼道，压迫感来自看不见，而不是血浆和写实贴图。

搬运即博弈：区别于「修发电机」式的站桩进度条，钥匙板是有实体、有重量的物件，扛起来就变慢，还能被抛、被抢、被摔在地上，天然产生追逃与反抢。

**单局 5 分钟**：面向碎片时间与直播节奏设计，一局一情绪曲线，不做长线消耗。

宿管也有信息劣势：追捕者视野受墙体遮挡、听觉有半径限制，而学生可以用一次刻意的抛投把她引开——高手可以「用声音和重量骗鬼」。

队友也是货物：扛起、抛出、接力传递队友，既是救援手段，也是最极端的诱饵——把室友扔向宿管换三秒时间，是允许的战术，也是要付代价的背叛。

多电闸箱 × 两扇门：目标点不是一个，逃生路线也不是一条。宿管守得越死，空出来的电闸箱与门就越多——「守」这件事本身变成了博弈。

快递柜里没人知道是什么：格口随对局时间逐个弹开，双方都能抢；捡起来的那一刻才按你的阵营开奖。抢快递和追人，是宿管每一局都要做的取舍。

# 二、核心玩法

## 2.1 核心循环

单局循环由六个动作串联：每一次搬运都在减速、在发声、在暴露位置，构成一条不断收紧的漏斗：

搜寻：在宿舍楼各楼层奔跑、跳跃、攀爬，翻找钥匙板，并留意楼道里逐个弹开的快递柜。

**搬运**：扛起重物，按重量分级降低移速、限制跳跃与攀爬，同时放大脚步声。

合闸：把钥匙板扛到任意一座未合闸的电闸箱前，插上钥匙板后守住读条 12 秒；读条被打断进度不清零，可以回来续上。

断电：合闸任意 3 座电闸箱，宿舍楼东西两端的两扇门禁同时断电弹开，整栋楼的应急灯一起亮起。

逃生或被抓：在倒计时内跑到任一扇门溜出去，或被宿管拦下拎回值班室。

**抛投与接力**：把物件或队友扔出去——可以撞开宿管换时间、抛上高台抄近路，也可以直接把钥匙板接力给队友，形成一次没有落地的运输。

循环之外还有一层「元循环」：局内的快递柜争夺（道具按阵营开奖）与局外的角色解锁，用于维持长期留存。

## 2.4 胜负判定

| 结果    | 触发条件                                                       |
| ----- | ---------------------------------------------------------- |
| 逃生者胜利 | 倒计时结束前，至少有 1 名学生从最左或最右的任一扇门溜出宿舍楼                           |
| 追捕者胜利 | 倒计时归零时无人逃出；或全部学生处于蹲地 / 被关在值班室状态且无人可救援                      |
| 评级结算  | 按逃出人数给出 S/A/B/C 评级，逃出 1 人为「惨胜」，4 人全逃为「完美开黑」；结算同时记录本局从哪扇门逃出 |

## 2.5 关键玩法规则

下表为 v0.4 立项版规则基线。搬运是本作的核心机制，其余规则均围绕「谁在搬、搬多重、能搬多久」展开。

| 机制     | 设计规则                                                                                                                                              |
| ------ | ------------------------------------------------------------------------------------------------------------------------------------------------- |
| 开局身份   | 服务器随机抽取一名真人玩家当宿管，其余玩家为学生；单机模式下由 AI 接管宿管                                                                                                           |
| 钥匙系统   | 每局 3 块钥匙板（4v1），从 6 个候选点随机刷新、分布在不同楼层；钥匙板是一块焊着整串钥匙的铁板，重 20–40 kg，必须扛在肩上运输                                                                           |
| 电闸箱合闸  | 宿舍楼固定 5 座电闸箱，每座需要插 1 块钥匙板；插好后读条 12 秒合闸，读条可被打断，但进度保留、可续读                                                                                           |
| 断电条件   | 合闸任意 3 座即触发全楼断电、东西两扇门禁弹开，剩下 2 座自动作废；队伍可以主动放弃被宿管守死的那几座                                                                                             |
| 两扇门    | 宿舍楼最西端（1F 消防通道铁门）与最东端（1F 垃圾房旁后门）各 1 扇；断电后保持敞开，进入门口区域 1 秒即逃出                                                                                       |
| 重量搬运   | 拿起后按重量分 **1~4 档**（每档 20 kg）：1 档（≤20 kg，红牛、手电筒）−10% 移速、跳跃攀爬正常；2 档（20–40 kg，钥匙板）−40%、禁慢走（Shift）、跳跃减半、不能攀爬；3 档（40–60 kg，蹲地的队友）−55%、不能跳不能爬、只能拖；4 档（>60 kg，纸箱 80 kg）−70%、只能拖行；不能瞬移或隔空传递 |
| 抛投规则   | 长按交互键蓄力 0.5 秒抛出，最远 6 米；扔队友砸中宿管造成 1.2 秒硬直，但宿管有 0.3 秒接住窗口，接住即直接被抓                                                                                   |
| 接力与托举  | 2 米内按 F 直接抛接物件，飞行中不可被抢；空手队友可托举把他人或重物推上 2 米高台                                                                                                      |
| 快递柜与道具 | 宿舍楼 8 个快递柜格口，开局弹开 3 个，之后每 45 秒自动再弹开 1 个；柜内是外观统一的「未知包裹」，双方都能捡，拾取瞬间按拾取者阵营从对应道具池随机发放                                                                 |
| 抓捕机制   | 宿管靠近玩家后，通过挥击削减其状态，再以交互键完成抓捕                                                                                                                       |
| 玩家被抓   | 首次被抓进入蹲地状态，队友可拉起，也可直接扛起搬走；二次被抓被拎进值班室，需队友撬门救出，超时淘汰                                                                                                 |
| 时间限制   | 倒计时结束仍无人逃出，追捕者获胜                                                                                                                                  |
| 联机方式   | 玩家通过房间号或好友邀请加入同一局，支持观战与中途补位                                                                                                                       |

# 三、系统设计

## 3.1 地图与关卡

结构：宿舍楼改为「纵向剖面」式多层地图——地下 1 层、地面 3 层、天台 1 层，共 5 个水平层；每层由一条东西走向的主楼道串起 2–3 个功能房间，层与层之间通过消防楼梯、铁梯、晾衣绳和一台货梯连接。横向总长约 210 米，层高 3.5 米（约两个角色高）。地图最西端是 1F 消防通道尽头的「左门」，最东端是 1F 垃圾房旁后门的「右门」——两者都在地面层，但一个在最西、一个在最东，几乎隔着整栋宿舍楼。

| 房间    | 功能定位             | 特征                     |

### 3.1.1 场景互动的统一规则

所有「走近了按一下就有反应」的东西，共用同一套规则。不按这套做的交互物，一律算设计错误。

**一、只有一把钥匙：E。**

拾取、开门、开柜、合闸、上床底、按灯开关，全部是 E，不出现第二个交互键。玩家走近任何可交互物，屏幕上只出现一句提示（例如「E 开门」），不需要记「这个用 E、那个用右键」。

**二、角色不知道面前是什么。**

角色身上只有一个「交互感应区」，它碰到东西时，只上报一句「我碰到了一个可交互物」，**不上报那是什么、也不决定怎么办**。判断是门还是柜子、该开门还是开柜，由楼层代理（见 §7.2）照清单处理。

这条是硬边界。W1 时期学生脚本里既管走跳、又负责找箱子找钥匙、还要喊界面亮格子，那种写法禁止再出现。

**三、可交互物按「会不会变」分三类，处理方式不同。**

| 类型 | 有哪些 | 存在形式 | 状态记在哪 |
| --- | --- | --- | --- |
| 死物（永不变） | 梯子、走廊灯、床底、窗 | 烘进图块层，**0 实例** | 不需要状态 |
| 活物（状态会变） | 钥匙板、可搬运小障碍 | 独立场景实例 | 物件自己身上 |
| 管理器型（一管多） | 门、快递柜、电闸箱 | 每层 1 个管理器节点 | 代理里的清单 |

**四、互动分两种节奏，不要混。**

| 节奏 | 长什么样 | 例子 | 实现要点 |
| --- | --- | --- | --- |
| 一次性触发 | 按一下就发生，做完就结束 | 开快递柜、捡道具、上床底 | 判断条件 → 执行 → 结束 |
| 持续状态（0~1 进度） | 按住/多次按，进度条慢慢走，中途可能被打断或被抢 | 开关门、电闸箱合闸 | 只记「进度」和「谁在推」，不记「归谁」 |

持续状态那类，进度**不清零**：被打断、被对方抢走，都保留当前进度，只换方向。这是「抢使用权」能成立的前提（门的细节见 §7.6.3）。

**五、每一样交互物都要能被「远程」操作。**

代理处理交互时，不靠「角色站在哪个坐标」临时算，而是照清单里记的物件位置判断距离。这样同一套代码既能处理门，也能处理柜子和电闸箱，加一样新东西只需要往清单里加一行。

**六、互动必须发出声音。**

这是本作的核心：学生每次交互都在给宿管报信（开门声、柜子弹开声、合闸的电流声）。声音的远近、是否被墙挡住，由 §7.6 的公平性机制统一处理，交互物自己不管音量——它只负责喊一声「我这儿发生了什么事」。

## 3.2 搬运系统（核心机制）

本作的核心不是「进度条」，而是「重量」。所有可搬物件与队友都有质量，扛起来立刻减速、立刻发出声响、立刻成为移动靶。

钥匙板（关键货物）：4v1 与 3v1 各 3 块，2v1 与 1v1 各 2 块（此时只需合闸 2 座电闸箱），从 6 个候选点随机刷新，候选点分布在不同楼层。

状态机：未发现 → 已发现（地面可见金属反光）→ 被携带（进入负重状态）→ 已插入电闸箱（锁定，不可再被抢走）；另有「掉落」「被抢」两个分支。

**重量分级（核心数值，2026-11-03 改为编号档）**：不再叫「轻 / 中 / 重 / 超重」，统一按 **1~4 档** 编号，每 20 公斤一刀；一件东西多重，就报「几档」。档位是唯一标准，给新物品标档只需写一个数字。

| 档位 | 重量区间 | 例子 | 移速 | 慢走(Shift) | 跳跃 | 爬梯 | 搬运姿势 |
|---|---|---|---|---|---|---|---|
| **1 档** | ≤ 20 kg | 红牛、手电筒 | −10% | 可 | 正常 | 可 | 抱在胸前 |
| **2 档** | 20–40 kg | 钥匙板、撬棍 | −40% | 禁 | 减半 | 禁 | 抱在胸前 |
| **3 档** | 40–60 kg | 蹲地的队友、床板 | −55% | 禁 | 禁 | 禁 | 拖在脚边 |
| **4 档** | > 60 kg | 纸箱（80 kg） | −70% | 禁 | 禁 | 禁 | 拖在脚边 |

分界就写在 `数据/重量档位.gd` 每行的「上限」里，改一个数字全场生效（比如 3 档想放宽到 70 kg，把 60 改成 70 即可）。3、4 档拖行时还会在地砖上蹭出很响的摩擦声。

**搬运代价**：负重时脚步声传播半径 +2 米，头顶显示负重光晕（仅宿管可见）；被挥击命中即掉落原地，5 秒内不可被同一人捡起；蹲地时必定掉落。

**队友搬运**：扛起蹲地的队友可先把他带到安全角落再拉起；扛人时不能跳、不能攀爬，只能走楼梯，消防楼梯因此成为最危险的必经之路。

**抛投**：长按交互键蓄力 0.5 秒后抛出手中的物件或队友，最远 6 米。抛出队友不造成伤害，但若砸中宿管，宿管硬直 1.2 秒、被抛者眩晕 1 秒——用室友换时间是允许的；但宿管有 0.3 秒的「接住」判定窗口，一旦接住，被抛者直接进入被抓。

**接力与托举**：两名学生相距 2 米内可按 F 直接抛接物件，飞行途中无法被抢，可实现跨缺口运输；第三名空手队友可「托举」把搬人者或重物推上 2 米高台，实现双人 / 三人协作越层。

**反蹲守与信息**：钥匙板掉落超过 45 秒无人拾取，自动回到随机候选点；钥匙板被拾起时全场播放一次金属碰撞声，但只有宿管能听到方向提示（3 秒衰减）。

## 3.3 电闸箱与左右两扇门

电闸箱规则：宿舍楼固定 5 座电闸箱，每座有一个钥匙孔。学生扛着钥匙板靠近，插进去（0.6 秒）后开始读条，持续 12 秒合闸；读条期间不能移动、不能攻击，被打断后进度保留（不清零），可以回来接着读。钥匙板一旦插进电闸箱就被锁定，不能再被搬走或抢走——双方争夺的不是钥匙板，而是这 12 秒。

为什么是多个电闸箱：只有一个目标点，宿管只要死守就能把节奏拖死；五座电闸箱分散在五个楼层，合闸任意三座即可，宿管永远守不过来。队伍也可以主动放弃被守死的一两座，改走别的路线——「放弃」本身就是一个战术决定。

两扇门：宿舍楼最西端（1F 消防通道铁门）与最东端（1F 垃圾房旁后门）各有一扇，两者相距约 200 米。第 3 座电闸箱合闸的瞬间，两扇门禁同时断电弹开并保持敞开，进入门口区域 1 秒即逃出。宿管跑得再快，也不可能同时守住两端——她必须赌一边。

合闸反馈：每合上一座电闸箱，箱体上方炸出一串电火花、整层楼道灯闪烁一次，全场可见；第 3 座合闸时，东西两扇门方向同时传来「嘀——」的断电长音，双方都知道「今晚只能跑了」。电火花也是给宿管的信息——它既是学生的里程碑，也是他们的位置暴露。

终局强化：第 3 座电闸箱合闸后，宿管移速 +8%，并且每 20 秒能透视搬运者 2 秒。学生必须在「继续搬剩下的钥匙板」和「立刻跑向门口」之间做最后一次取舍。

门口拦截：门口通道宽 1.2 米，宿管可以站在通道里用身体阻挡，也可以挥击正在通过的学生；但被抛出的队友可以把她撞开 1.2 秒——这是「把室友当武器」最后的用途。

| 学霸（白）  | 打气   | 主动：原地 2 秒，为 8 米内队友解除减速与眩晕并恢复半格血；被动：救援读条 −25%                | 40 秒 |
| 摄影社（红） | 闪光灯  | 主动：前方 6 米扇形致盲宿管 1.5 秒；被动：奔跑脚步声半径 −30%                       | 35 秒 |
| 吃货（黄）  | 泡面   | 主动：放下泡面桶（存在 20 秒），队友吃下 5 秒内移速 +15%，宿管踩到滑倒 1 秒；被动：所有负重减速 −5% | 45 秒 |

## 3.5 追捕者能力与角色技能

宿管不是「全图透视的怪物」，而是一个同样受重量约束的追捕者——她拎着蹲地的学生往值班室走时自己也会变慢，这就是学生的机会。

| 能力   | 规则                      | 数值                          |
| ---- | ----------------------- | --------------------------- |
| 巡逻移动 | 沿预设路径点巡视，转向有惯性          | 3.8 m/s                     |
| 追击移动 | 发现目标后切换，略快于逃生者          | 5.4 m/s                     |
| 视野   | 前方扇形视野，被墙体遮挡            | 角度 100°，距离 9 米              |
| 听觉   | 无视线时的声音感知，搬运者的声响范围更大    | 基础 2.6 米；搬运重物者额外 +2 米       |
| 攻击   | 有前摇的挥手拍打，命中造成一格伤害       | 范围 1.5 米，前摇 0.38 秒，CD 1.0 秒 |
| 抓捕   | 贴身长按完成抓捕                | 1.2 秒读条，被打断则重置              |
| 拎走   | 把蹲地者拎进最近的值班室，拎人时自己也会变慢  | 拎人时移速 2.4 m/s               |
| 接住抛投 | 可接住被扔过来的逃生者，接住即直接进入抓捕   | 判定窗口 0.3 秒，接住后自身硬直 0.6 秒    |
| 手电扫过 | 每次学生合闸电闸箱，获得合闸者方向提示     | 指向 2 秒，不显示距离                |
| 锁楼广播 | 第 3 座电闸箱合闸、两扇门断电弹开后获得增益 | 移速 +8%，每 20 秒透视搬运者 2 秒      |

打断合闸：宿管的挥击命中正在读条的学生时，读条立即中断（进度保留）；这是宿管阻止合闸的主要手段，也是学生必须留人掩护的原因。

三名首发宿管也各有 1 个主动技能与 1 个被动，分别对应「信息、控制、潜行」三种打法：

| 追捕者  | 主动技能 | 效果（含被动）                                                                    | 冷却   |
| ---- | ---- | -------------------------------------------------------------------------- | ---- |
| 宿管阿姨 | 听墙角  | 主动：3 秒内全场搬运者显示方向光晕（不显示距离）；被动：楼梯与货梯上移速 +10%                                 | 25 秒 |
| 保洁阿姨 | 拖把横扫 | 主动：1.5 米扇形击落学生手中的货物（不造成伤害），货物 3 秒内不可拾取；被动：提前 15 秒看到下一个快递柜格口弹开的位置（学生只有 5 秒） | 12 秒 |
| 保安大叔 | 关灯巡逻 | 主动：8 秒内脚步声消失、移速 −10%；被动：5 米内有玩家跳跃或落地时，短暂显示其轮廓 1 秒                          | 30 秒 |

AI 行为状态机（单机模式）：巡逻 → 察觉（听到声响 / 瞥见轮廓）→ 搜索（在最后已知位置附近绕圈 3.6 秒）→ 追击 → 挥击 → 抓捕 → 归位巡逻；若有人正在电闸箱前读条，优先冲过去打断；若发现有人扛着东西，优先追击负重者。状态切换必须有 0.4 秒以上过渡，避免「瞬移式转向」破坏可读性。

## 3.6 快递柜与道具

快递柜规则：宿舍楼固定 8 个快递柜格口，开局只有 3 个会弹开；此后每 45 秒自动再弹开 1 个，弹开时柜门「啪」一声并亮起一串蓝光，全场都能看见位置。快递柜不需要钥匙板，也不需要读条，谁先摸到谁先拿。

未知包裹：柜里取出的东西外观完全一致（一个缠着胶带的纸箱），双方都能捡；拾取的一瞬间，系统才按拾取者的阵营从对应道具池随机开奖。学生永远不知道自己抢到的会不会是给宿管用的东西——反过来也一样。

| 道具       | 获取        | 效果                             | 携带上限 |
| -------- | --------- | ------------------------------ | ---- |
| 红牛       | 快递柜（学生拾取） | 4 秒灌完恢复一格，喝的时候会发出响亮的易拉罐声       | 2    |
| 灭火器      | 快递柜（学生拾取） | 喷出后 4 米范围视野遮蔽 3 秒，宿管视野锥失效      | 1    |
| 手电筒（放置式） | 快递柜（学生拾取） | 插在地上形成 3 米光源，用来引诱宿管走开；只照明，不能致盲 | 2    |
| 撬棍       | 快递柜（学生拾取） | **⚠️ 待主人定**：门的规则改成「双方抢使用权」后，「秒开寝室门、跳过开门耗时」已失去意义（学生本来就 0.3 秒）。建议方向：撬棍改为「从内侧把门钉死」，宿管需要额外 N 秒才能破开，数值待定 | 1    |

宿管道具池（同样来自快递柜）：

| 道具  | 获取        | 效果                               | 携带上限 |
| --- | --------- | -------------------------------- | ---- |
| 粘鼠板 | 快递柜（宿管拾取） | 放置在地面，学生踩中定身 1.5 秒并发出巨响；可花 2 秒撕开 | 1    |
| 封条  | 快递柜（宿管拾取） | 封死一扇门或一段通道 8 秒，学生需 3 秒撕掉         | 1    |
| 对讲机 | 快递柜（宿管拾取） | 10 秒内显示最近一名搬运者的方向（不显示距离）         | 1    |

设计意图：快递柜把「时间」变成了可争夺的资源——宿管去抢快递，就少追一会儿人；学生去抢快递，就要冒被撞见的风险。格口弹开时的蓝光是双方共享的信息，谁先到、谁放弃，都是判断。

道具设计原则：所有道具都同时具有「帮自己」与「骗对手」两种用法，并且都能被搬起、抛出、接力——重量让每一次携带都要付出代价。

## 3.7 节奏与压力曲线

单局必须呈现「松—紧—更紧—爆发」的四段压力曲线。

| 时间        | 逃生者体验           | 追捕者体验          | 系统手段                |
| --------- | --------------- | -------------- | ------------------- |
| 0:00–1:00 | 探索、抢第一批快递       | 巡逻、记快递柜位置      | 开局 3 个格口已弹开         |
| 1:00–2:30 | 找到第一块钥匙板，开始扛运   | 听到第一声金属碰撞，开始搜索 | 钥匙板拾取音、快递柜持续弹开      |
| 2:30–4:30 | 合闸电闸箱、抢快递、被抓与救援 | 打断读条、守电闸箱、抢快递  | 每合闸一座触发手电扫过；快递柜持续弹开 |
| 4:30–结束   | 跑向左右两扇门         | 赌一边守门与反打       | 第 3 座电闸箱断电开双门、锁楼广播  |

若 4 分 30 秒时仍未合闸任何电闸箱，系统触发「熄灯广播」：楼道灯逐段熄灭，只留通往电闸箱的一条路亮着，并让某一层的铁门自动「砰」一声，主动把双方赶到一起，避免对局空转。

## 3.8 局外成长

保持「轻成长、重技术」的克制设计，避免付费即强：

角色解锁：首发 4 名学生 + 3 名宿管（正式版扩到 6 + 3），每人 1 个主动技能 + 1 个被动，通过局内经验解锁，不出售数值。

**外观**：皮肤、拖鞋样式、结算动作，纯装饰。

**熟练度**：单一角色使用场次解锁专属台词与立绘，强化角色情感连接。

## 4.2 目标胜率与节奏指标

| 指标        | 目标值             | 说明                   |
| --------- | --------------- | -------------------- |
| 逃生者胜率     | 45%–55%         | 以「至少 1 人逃出」为胜        |
| 平均逃出人数    | 1.6 人 / 4 人     | 体现「惨胜」为主的情绪基调        |
| 平均单局时长    | 5 分 30 秒 ± 60 秒 | 超出 8 分钟视为节奏失败        |
| 首座电闸箱合闸时间 | 中位数 2 分 10 秒    | 早于 1 分 30 秒说明钥匙板过于集中 |
| 平均救援次数    | 1.2 次 / 局       | 低于 0.5 说明救援风险过高      |
| 左右门使用比例   | 40%–60%         | 若长期偏向一侧，说明另一侧路线过长或过险 |

## 4.3 平衡杠杆

当胜率偏离目标时，按以下顺序调整，每次只动一个变量：

**钥匙板刷新密度**（调候选点数量）——影响最大，最不伤手感。

重量减速系数（以 2 档 −40% 为基准上下浮动 5%）——直接影响搬运风险。

**宿管听觉半径**（2.6 米 ± 0.4 米）——影响信息压迫强度。

电闸箱读条时长（12 秒 ± 2 秒）——影响终局紧张度。

**蹲地倒计时**（90 秒 ± 15 秒）——影响救援窗口。

抛投力度与宿管接住判定窗口（最远 6 米 / 0.3 秒 ± 0.05 秒）——决定「扔室友」是救命还是送人头。

断电所需电闸箱数量（3 座，可试调 2–4 座）——影响目标分散程度。

快递柜弹开节奏（45 秒 ± 10 秒）——影响双方在中期的资源分配。

## 4.4 反滚雪球机制

学生每有一人蹲地，其余学生获得 5% 移速加成（最多 15%），俗称「背水一战」。

宿管每次成功抓捕后，视野半径短暂缩减 20%（2 秒），给其他学生喘息窗口。

连续两座电闸箱由同一人合闸时，该玩家获得「标记」，宿管可透视其 3 秒——奖励团队分工，抑制单人带飞。

## 5.2 HUD 布局

左上：圆形小地图，只显示已探索区域，队友以蓝点、钥匙板以金点、电闸箱以紫色菱形、弹开的快递柜以蓝箱图标、宿管以红雾（仅在她发出声响时短暂显示）；横版视角下额外画出楼层线，标出当前所在层，左右边缘各有一个门口箭头。

右上：倒计时 + 合闸进度（如「2 / 3」，已合上几座、还差几座）+ 左右两扇门图标（断电后点亮并闪烁）。

**左下**：两格状态条（体力 / 状态位，具体等体力系统定稿）。

右下：当前携带物图标、**档位**与实时移速修正（如「2 档 −40%」），以及交互提示文字（如「按住 E 扛起室友」）。

**底部中央**：危险度环——随宿管距离与视野朝向动态收缩，是玩家唯一的「第六感」。

**底部左侧：负重条**——随重量逐级填色（绿 / 黄 / 橙 / 红），跳上高台前一眼就能判断自己这一跳够不够得着。

读条条：站在电闸箱前读条时，屏幕中央出现 12 秒进度条；被打断后进度条变灰但不清零，回来接着读。

快递柜提示：下一个格口将在 5 秒后弹开时，小地图对应位置开始闪烁；弹开瞬间全场播放一次开柜音与一串蓝光。

# 六、美术与音频

## 6.1 2D 像素风定义

| 维度  | 规范                                                                  |
| --- | ------------------------------------------------------------------- |
| 上色  | 严格有限色板：全局不超过 24 色，单角色 8–10 色；禁用渐变与半透明过渡，靠三档明度表现体积                   |
| 描边  | 统一 1 px 深色描边（16 px 基准下的 1 像素），色值随环境光偏移，不用纯黑                         |
| 比例  | 角色约 24×32 px（2.5 头身），横版侧视，左右镜像复用；头部略大以增强辨识                          |
| 配色  | 主色板：夜蓝 #1B2440、路灯黄 #F2C777、校服白 #E8EAF0、警示红 #D9534F；全部压进 24 色内       |
| 渲染  | 纹理过滤 Nearest、只允许整数倍缩放、禁止旋转与非整数位移；相机与角色位置按整数像素对齐，避免抖动与糊边             |

## 6.2 角色设定

逃生者（4 名）：游戏宅、学霸、摄影社、吃货。服装明度偏高，确保在暗场景中可辨识；每人一个标志性配色（青、白、红、黄），横版侧视下靠配色与剪影认人。四人的技能与外观一一对应：游戏宅轻快、学霸沉稳、摄影社利落、吃货壮实。

追捕者（3 名）：宿管阿姨、保洁阿姨、保安大叔。剪影夸张，肩宽与臂展大于学生 1.3 倍，形成压迫感；宿管与保洁只画出手电光下的半张脸，保安大叔帽檐压得很低、只看得见手电光柱。宿管阿姨厚重、保洁阿姨纤细而动作快、保安大叔几乎不出声。

## 6.3 场景与特效

**场景**：水磨石地砖、剥落的墙皮、楼道里贴满的小广告三档随机，避免整片平铺的重复感。

特效：走廊感应灯忽明忽暗（顶点动画）、灰尘粒子、钥匙板金属微光（呼吸式透明度）、电闸箱合闸时的电火花与光柱、门禁断电时的门缝光束与浮尘、快递柜弹开时的蓝色光柱。

**禁止**：不做血腥溅射、不做断肢，紧张感全部由光影、音效与构图承担。

## 6.8 光照与可见性

| 光源      | 范围             | 看得见什么 / 暴露代价                                 |
| ------- | -------------- | -------------------------------------------- |
| 学生·自发光  | 自身周围 1.5 米     | 能看清脚下与近身地形；全楼本身是微光可见（走路不会撞墙），但看不清细节          |
| 学生·手电·开 | 前方 6 米 × 25° 锥 | 能看清并识别可交互物（钥匙板、快递柜、电闸箱、道具）；宿管在 12 米内能看见光点与方向 |
| 学生·手电·关 | 自身 1.5 米       | 完全不被察觉，但无法发现任何可交互物                           |
| 当搬着货时   | 缩短到 4 米        | 光被身体挡住一部分，且搬货本身已是显眼目标                        |
| 寝室小灯    | 房间全亮           | 房间内一切清晰；宿管在 20 米外就能看见这间房亮着，离开 5 秒后自动熄灭       |
| 宿管·手电   | 8 米 × 30° 锥    | 照到学生 1.5 秒使其暴露 3 秒；被照者视野发白                   |

规则一：手电不能致盲，学生没有任何致盲手段。随身挂灯只负责「看清并找到东西」，照到宿管只会被察觉位置；能打断宿管的只有两样——灭火器喷出的白雾让她的视野锥失效，以及把队友扔过去换来的 1.2 秒硬直。

规则二：不开手电也能走，但找不到东西。全楼是微光可见的，学生凭自发光就能跑动、跳跃、上下楼；只有打开手电，钥匙板、快递柜、电闸箱、道具这些「细节」才会被识别出来——所以手电是信息工具，不是移动必需。

规则三：光就是代价。手电开着，宿管在 12 米内就能看见光点与方向；关掉则完全隐没，但什么也找不到。玩家每走两步都要做一次「要不要开灯」的决定，而宿管也因此获得一条不依赖视野的信息线索——这是双方信息不对称的平衡点。

# 七、技术方案

## 7.1 引擎与渲染

**引擎**：Godot 4.7，GDScript 为主，热点逻辑（寻路、视野计算）用 Typed Array 与空间分区优化。

渲染：Forward+ 渲染管线，2D 光照与遮挡；纹理过滤统一 Nearest，画面只做整数倍缩放（640×360 基准 → 1920×1080 恰好 3 倍），相机按整数像素对齐，避免像素抖动与糊边；全屏后处理使用单 pass 着色器实现暗角与色差。

**性能目标**：1080p / 60 FPS，GTX 1050 级别显卡稳定；内存占用低于 800 MB。

**手机端是硬约束**：本作**要能上手机**。凡是与手机性能冲突的方案一律让路——这条排在画面效果、开发便利之前。具体表现为「死物不进实例、活物才建节点」，详见 7.6.2。判断标准不是「电脑上跑得动」，而是「手机上不发烫、不卡顿」。

## 7.2 场景与节点结构

**总架构一句话：一个总管控全局，各层各有各的代理。**
这是本作的技术骨架，不是可选风格。所有场景、交互物、界面都必须按这个分法归位，不允许绕过。

```
总管（顶层管线：负责接收与转发各系统的信号，全局唯一）
│
├── 状态机 ── 动作 ── 玩家 ── 学生（求生者）
│                        └── 宿管阿姨（追捕者）
│
├── 场景 ── 可交互的物品 ─┐
│       └─ 可交互的场  ──┴── 记录与玩家的互动
│
└── 公平性机制 ── 造成什么影响（玩家不同的行为，发出不同的声音）
```

落实到工程里的三层（2026-11-02 已实现并跑通）：

| 层 | 文件 | 职责 | 不做什么 |
| --- | --- | --- | --- |
| 总管 | `单例/场景总管.gd`（autoload 名 `Director`） | 记「哪一层归谁管」，把话递过去 | 自己不干活，不管门怎么开 |
| 楼层代理 | `场景/楼层代理/楼层代理.gd` | 读清单 → 建这一层的东西 → 照单处理事件 | 不管别的层，不管角色怎么动 |
| 清单（数据） | `数据/楼层清单.gd` | 这层有什么、在哪个坐标 | 不含任何逻辑 |

**分层铁律**：角色（学生/宿管）不知道门在哪、灯在哪、装了哪些东西。角色只负责「我碰了东西」然后往上报，由总管找对应楼层的代理处理。以前学生脚本里既管走跳、又管找箱子找钥匙、还要喊 UI，这种写法**禁止再出现**。

**加一层楼的成本必须是零**：同一份代理脚本，改 `floor_id` 挂到新楼层即可；新楼层放什么，只加一份清单，不写代码。

## 7.3 网络同步

| 项目        | 方案                                            |
| --------- | --------------------------------------------- |
| 拓扑        | 主机权威（Host-Authoritative），主机同时充当一名玩家           |
| 传输        | ENet，可靠通道走状态事件，不可靠通道走位置快照                     |
| 快照频率      | 20 Hz，位置做线性插值 + 200 ms 延迟缓冲                   |
| 客户端预测     | 仅本地移动做预测，交互与伤害全部由主机裁定                         |
| 反作弊       | 主机端校验移动速度上限与交互距离，超限回滚                         |
| 搬运状态      | 「谁扛着谁 / 什么」由主机裁定并广播；客户端只做抛物线与落地表现的插值          |
| 电闸箱与快递柜状态 | 电闸箱合闸进度、快递柜弹开倒计时、门禁断电状态由主机统一广播；客户端只播放表现，不自行判定 |

选择主机权威而非帧同步的原因：本作是 5 人小局、状态量小、对「确定性」要求低，主机权威实现成本最低且易于中途加入。

## 7.6 架构与协作铁律（AI 必读）

> 本节是给「接手这个项目的 AI」看的。读完这一节，不需要再看别的文件，就知道这个项目为什么这样搭、哪些做法绝对不许做。每一条都是踩过坑之后定下来的，不是建议。

### 7.6.1 分类原则：死物进图块，活物才建节点

**能搬的东西才是实例，不能搬的东西一律烘进图块层。**

| 东西 | 数量级 | 做法 | 实例数 |
| --- | --- | --- | --- |
| 门、走廊灯、床底、窗、小广告、墙角 | 上百个 | 画进 TileMapLayer | **0** |
| 梯子 | 每层 2~3 架 | 画进图块层，爬梯判断改成「查脚下那一格是不是梯子图块」 | **0** |
| 钥匙板 | 每张图 3 块（6 个候选点抽 3） | 独立实例（要能扛、能丢、状态会变） | 3 |
| 可搬运小障碍 | 0~20 个，很多图一个都没有 | 独立实例 | 0~20 |
| 快递柜 | 固定 8 个格口 | **每层 1 个管理器**管这层所有格口，不拆成 8 个节点 | 1 |
| 快递柜里的物品 | 随刷随取 | **不占实例**，就是柜子身上一张贴图；捡起来直接进 UI 数据，图上隐藏 | **0** |
| 学生 / 宿管 | 1~5 | 独立实例 | 1~5 |

**一张图的总实例数控制在 6~30 个。** 超过这个数就是设计出错了，不是性能不够。

**为什么**：手机端 Drawcall 一多就发热掉帧；而更致命的是维护成本——5 层楼、每层手摆几十个节点，改一个「走廊灯亮度」要改几十处，这才是真正会爆炸的地方。

### 7.6.2 禁止的做法（出现过，别再犯）

1. **不许把界面挂在角色身上**。UI 归界面，角色只广播事件（例：学生拿到道具只喊一嗓子，道具格自己决定怎么亮）。W1 因为这条返工过一次。
2. **不许让角色自己去场景里找东西**（`get_overlapping_areas()` 扫全世界然后判断类型）。角色只上报「我碰了交互」，由楼层代理判定是哪一样。
3. **不许为了省节点把多个独立感应区合并成一个**。爬梯感应（细长、贴身子）和捡拾感应（宽松）必须分开，否则范围被绑死、事件互相干扰。
4. **不许在脚本里写死坐标**。所有位置来自 `数据/` 清单，改位置只改表。
5. **不许跑性能压力测试来"证明"能跑**。无头模式不渲染，测不出 Drawcall，结论是假的。判断性能看的是「实例数和绘制次数」，不是帧时间。

### 7.6.3 门：双方抢使用权

寝室门**不是**一次性障碍，而是**可以反复争夺的节奏控制点**。两方都能开、都能关，只是快慢不同：

| | 开门 | 关门 |
| --- | --- | --- |
| 求生者 | 0.3 秒 | 0.3 秒 |
| 宿管 | 1.5 秒 | 1.5 秒 |

**「抢」的判定方式**：门只记两个数——开到哪儿了（0~1）、现在是谁在推。谁后按，谁就接管这扇门，方向立刻反转，**进度不清零**。所以宿管推到 34% 时求生者一按，门从 34% 开始往回关，且按求生者的速度关。

宿管站在电闸箱 3 米内时，开门再慢 50%（W4 接入）。

### 7.6.4 快递柜：固定位置，随机选格

8 个格口位置固定，**开局随机挑哪些格口弹开**，之后按固定间隔再弹一个。不做「随机位置生成」——那需要可达点池 + 防堵路逻辑，收益远小于成本。

### 7.6.5 与 AI 协作的规矩

1. **AI 给的任务卡不能全信**。整体框架稳定，但细节会与工程实际不符，必须核对后再执行。
2. **每一次改动，设计者都必须知道改了哪里、为什么**。不允许静默修改结构。
3. **要出「参考答案」**：带大量注释、不参与正式架构、单独放 `参考资料/`，方便设计者自己改一遍学、也方便以后整份删除。
4. **一个模块做不下去就拆模块**，不许硬做——硬做必然把工程搞乱。
5. **不懂就问，至少把概念弄清楚**。概念不清，后面的模块就拆不开。
6. **目录规范以工程根 `目录规矩.md` 为准**，新东西先看那张表再决定放哪。

# 九、练手目标与验收

本作是阶段性练手产物：不商业化、不上架、不做运营。验收标准不是销量，而是「下面这七件事我能不能自己说清、自己改得动」——注意第 ⑤ 条不是「会用信号」这么简单，是「能画出依赖图、能讲清一次崩掉的牵连」。

① 游戏节点认知：能画出完整场景树，说清 Scene（场景）与 Node（节点）的区别、每个节点负责什么、为什么这样拆。落点见 7.2 节点结构。

② 基础 GDScript 编写：变量、函数、if 分支、for 循环、数组与字典、导出变量，能读懂项目里每个脚本在干什么，并能自己加一个小功能。

③ 地图设计：用 TileMapLayer 拼出五层宿舍楼，设置碰撞体、单向平台、铁梯与晾衣绳的攀爬区，并能自己改一层楼的布局。

④ 状态机：玩家状态（空手 / 负重 / 被逮 / 蹲地 / 合闸中）与宿管 AI（巡逻 → 察觉 → 搜索 → 追击 → 挥击 → 抓捕）各一张状态表，切换条件写清楚。

⑤ 信号与低耦合（事件中枢）：一句话——谁都不许直接伸手去掏别人的口袋，有事就喊一声，谁需要知道谁自己来听。货物掉落、合闸完成、快递柜弹开、门禁断电，都只由当事节点喊，喊的人不需要知道有谁在听，听的人也不需要知道是谁喊的。验收两条：能画出「谁跟谁连着」的依赖图，图上任意两个系统之间只有一条经中枢的线、没有一条直连；能举出一个「我改了 A、结果 B 崩了」的旧例子，并讲清当初为什么会崩。

耦合到底指什么（大白话）：两个东西只要互相认识，就算「绑在一起」了。绑得越紧，动一个就得动另一个，牵一发而动全身——这叫高耦合。低耦合不是「不联系」，而是「只跟值班室联系」：楼里所有事都报到值班室，A 有事告诉值班室，值班室再转给 B，A 一辈子不需要认识 B。这样以后楼里多住进来一个人，A 不用改一个字。

但值班室不能变成「什么都管」：它只负责传话，不负责替别人做决定。一旦它开始判断「这是宿管，所以应该……」，它就变成了所有人的靠山，最后所有代码又都绑回这一个文件上，比原来还糟。检验方法很土但很准：随便掐掉一个系统（比如音效），游戏还能跑，只是变安静了——那就是对的；掐掉音效游戏直接崩，那就是耦合跑错了地方。

| 场景      | 会咬人的写法（高耦合）              | 松开的写法（低耦合）                  |
| ------- | ------------------------ | --------------------------- |
| 快递柜弹开   | 柜子自己去找到 HUD，改那句提示文字      | 柜子只喊一声「我开了」，HUD 自己来听        |
| 合闸完成    | 电闸箱自己去改进度、自己去通知宿管、自己去点亮门 | 电闸箱只喊「第 2 座合上了」，进度、门、宿管各自来听 |
| 玩家被抓    | 玩家脚本直接伸手去取消队友的救援读条       | 玩家喊「我被抓了」，救援系统自己取消          |
| 想加一个新道具 | 要回头改六个地方，漏一个就出 bug       | 只在道具表里加一行，别的文件一个字不动         |
| 掐掉音效系统  | 游戏直接报错，跑不起来              | 游戏照常跑，只是变安静了                |

⑥ 层级与父子关系：场景实例化、CanvasLayer 与 HUD 层级、Y-Sort 前后遮挡、跨层引用方式（get_node / @export / 信号），能解释「为什么不能随便跨层直接调用」。

⑦ 光源与光照（本次新增的突破项）：用 CanvasModulate 把整栋楼压黑，用 Light2D 与遮罩做出「光锥之内的能看清、之外是黑的」；能自己调手电的锥角、射程与衰减，能让寝室小灯只照亮一个房间，能解释「为什么关灯就看不见可交互物」。这一项是前两个项目都没碰过的地皮，属于本作的核心增量。

明确不做（练手范围外）：不商业化、不付费、不做成就、不做排位与赛季、不做手机端、不做本地化。省下来的时间全部投到上面七项。

执行规则（边做边学，不做系统上课）：比例按周浮动——W1–W2 学 50% / 做 50%，W3–W5 学 20% / 做 80%。一旦卡住，补课限时 2 小时：① 到点不论学没学透，先回项目改一行、跑一次；② 只补当下卡住的那一个概念，不许顺着教程往下翻；③ 用一句话自测「我要它干什么、它现在干了什么」——说得出来就继续做，说不出来才停下来学；④ 每周日固定一次系统补课，把这一周撞过的墙统一补一遍。
