## 〇、明天收工时，手上应该有什么

一个能按 F5 跑起来的 Godot 窗口：左边一个灰方块，按 A/D 左右走，按空格跳，按住 Shift 慢走。**别的什么都没有，这就是达标。**

验收清单（7 条全过才算完成）：

- [ ] 按 D 方块向右加速，约 0.1 秒到全速，**不是瞬间起飞**
- [ ] 松开 D 之后还滑一小段才停，**不是立刻刹住**
- [ ] 按空格能跳起来，跳起约 2.2 米（脚底离地约 72 像素，大约一个半身位）
- [ ] 跳到半空松开空格，**上升立刻变矮**（这叫可变跳高）
- [ ] 站在地上按空格立刻跳，**没有延迟**；离开平台边缘后 0.1 秒内仍能起跳
- [ ] 按住 D（或 A）时按 Shift，方块"咻"地窜出去一大截，**速度瞬间拉满、不走加速**
- [ ] 冲完立刻再按 Shift 没反应，约 1.5 秒后又能冲（这叫冷却）

## 一、第 1 件：建工程和目录（约 40 分钟）

### 1.1 新建项目

1. Godot 4.7 启动器 → 新建项目 → 路径选 `D:\Github\阿姨别追`（就是现在这个文件夹，不是子文件夹）
2. 渲染器选 **Forward+**（策划案定的；后面 2D 光照要用）
3. 版本控制选 Git（如果弹出来），没有就跳过

### 1.2 三个项目设置（这步最容易被跳过，但跳过后全是坑）

| 去哪儿 | 改什么 | 改成 |
| --- | --- | --- |
| 项目设置 → 显示 → 窗口 | 视口宽度 / 高度 | 640 / 360（这是"逻辑分辨率"，最后会放大到全屏） |
| 同上 → 窗口 | 窗口宽度覆盖 / 高度覆盖 | 1920 / 1080（和策划案「1080p 性能目标」对齐） |
| 同上 → 拉伸 | 模式 / 比例 | `viewport` / `keep` |

再改一个：

| 去哪儿 | 改什么 | 改成 |
| --- | --- | --- |
| 项目设置 → 渲染 → 纹理 | 默认纹理过滤 | `Nearest`（最近邻） |

**为什么要这样**：像素风的核心是"一个像素就是一个方块"。逻辑分辨率 640×360、最后整倍放大到 1920×1080，每个像素正好变成 3×3 的方块，边缘是硬的。用默认设置的话，引擎会做平滑插值，像素画放大后是糊的——而且一旦糊了，后面画的所有图都得重画。

### 1.3 建目录（照技术框架 §四，只建明天要用的）

在文件系统面板里右键 `res://` → 新建文件夹，建这些：

```
单例/      场景/      角色/      组件/      数据/
```

先只建这五个，其余（交互物、效果、素材、测试）等要用的时候再建，别一次建一堆空文件夹。

### 1.4 项目设置里确认物理帧

项目设置 → 物理 → 通用 → 物理帧率 = **60**（默认就是，确认一下）。

**为什么是 60**：物理帧是"游戏世界的时钟"。60 表示每秒固定算 60 次移动和碰撞，不管你电脑跑 30 帧还是 240 帧。这样四个人联机时，大家的物理运算节奏一致——这是联机能对上的前提。如果跟着渲染帧走，快电脑的人和慢电脑的人会算出不同结果。

### 1.5 建一个常量单例

新建 `单例/游戏设置.gd`：

```gdscript
extends Node

const PIXELS_PER_METER: float = 32.0

func m(meters: float) -> float:
    return meters * PIXELS_PER_METER
```

然后：项目设置 → 全局 → 自动加载（Autoload）→ 路径选这个文件 → 节点名写 `GameSettings` → 添加。

**为什么要这个**：策划案里所有数值都是"米/秒"（学生 4.6 m/s、跳跃初速 7.2 m/s），但引擎只认像素。定死 **1 米 = 32 像素**，以后看到策划案的数字直接 `GameSettings.m(4.6)` 就能用，不用每次心算。改比例也只改这一个数。

**注意**：自动加载的节点名必须是纯英文（`GameSettings`），文件名可以用中文。中文名的自动加载会被引擎按错误编码解析成乱码——代号宝石项目踩过这个坑，报错信息里完全看不出原因。

## 二、第 2 件：让方块走起来（约 1.5 小时）

### 2.1 搭场景，按技术框架的骨架来

新建场景 → 根节点选 `Node` → 存为 `场景/main.tscn`。结构长这样：

```
main（Node）                    ← 常驻根，以后永远不换这个场景
└── World（Node2D）             ← 空容器。以后切地图只换它的子节点
```

**为什么现在就要这一层 `World`**：技术框架 §9.2 定的规矩。明天虽然只有一张测试图，但结构先摆对，等到 W5 接联机时，"切地图"就只是清空 `World` 的子节点，不用拆整个场景。今天省这一步，五周后要还三天的债。

### 2.2 做一个测试地板

新建场景 → 根节点 `StaticBody2D` → 存为 `场景/测试关.tscn`：

```
测试关（StaticBody2D）
├── 外观（ColorRect）            ← 占位，深灰色，尺寸 2000 × 80，位置自己摆
└── 碰撞（CollisionShape2D）     ← RectangleShape2D，尺寸 2000 × 80，位置填外观的中心点
```

> **碰撞位置怎么算**：`ColorRect` 的位置是它的**左上角**，`CollisionShape2D` 的位置却是矩形的**中心**。比如外观放在 (0, 0)，碰撞就得填 (1000, 40)——宽的一半、高的一半。十有八九的悬空/穿地 bug 都是这两个没对上。

把这个 `测试关.tscn` 拖进 `main` 的 `World` 下面，变成实例。

> **为什么要两个东西**：`ColorRect` 只是画出来的样子，`CollisionShape2D` 才是"真正撞得住"的边界。两个不对齐的话，就是你看到方块陷进地板里、或者悬在地板上方。这是新手第一天最常见的坑，先记着。

### 2.3 做学生

新建场景 → 根节点 `CharacterBody2D` → 重命名 `学生` → 存为 `角色/学生/学生.tscn`：

```
学生（CharacterBody2D）
├── 外观（ColorRect）            ← 20 × 44，浅色，位置 (-10, -44)
└── 碰撞（CollisionShape2D）     ← RectangleShape2D，20 × 44，位置 (0, -22)
```

**注意位置那些负数**：Godot 里节点原点是它的"脚底中心"会更方便。所以外观往左上挪（宽度一半、整高），碰撞往上挪半个身高。这样 `学生.position` 就是"他站的那个点"，以后算距离、放出生点都直观。

**为什么是 20×44 像素**：按 1 米 = 32 像素算，44 像素≈1.37 米，是个偏矮的成年人轮廓。像素风游戏里角色一般故意画矮一点，显得楼更高、更有压迫感。

### 2.4 接输入

项目设置 → 输入映射 → 加四个动作（**名字必须全小写英文**）：

| 动作名 | 绑什么键 |
| --- | --- |
| `move_left` | A、左方向键 |
| `move_right` | D、右方向键 |
| `jump` | 空格 |
| `sprint` | Shift（左右 Shift 都行） |

**为什么要用"动作名"而不是直接读按键**：以后要加手柄、要支持改键，只改这张表，代码一个字不动。直接写 `Input.is_key_pressed(KEY_D)` 的话，将来加手柄要把所有代码翻一遍。

### 2.5 写移动代码

给 `学生` 挂一个脚本 `角色/学生/学生.gd`：

```gdscript
extends CharacterBody2D

const SPEED: float = 147.0          # 4.6 m/s × 32
const ACCEL: float = 1400.0         # 加速度：越大越"跟手"
const FRICTION: float = 1800.0      # 松手后的减速度

func _physics_process(delta: float) -> void:
    var dir := Input.get_axis("move_left", "move_right")
    if dir != 0.0:
        velocity.x = move_toward(velocity.x, dir * SPEED, ACCEL * delta)
    else:
        velocity.x = move_toward(velocity.x, 0.0, FRICTION * delta)

    move_and_slide()
```

保存，把 `学生.tscn` 也拖进 `World` 下面（和测试关平级），F5 运行。

**验收**：按 D 能往右走，松开滑一小段停住。走不出屏幕就对了（还没写相机）。

**这里有两个必须搞懂的点**：

1. `move_toward` 是"朝目标值靠近最多这么多"，所以它天然就是加速过程。你如果写成 `velocity.x = dir * SPEED`，方块会瞬间满速，看起来像瞬移——这就是"手感"的差别。
2. `move_and_slide()` 是引擎帮你做的：按速度移动 + 撞到东西停下 + 沿斜坡滑。**你一行碰撞代码都不用写。** 自己算碰撞是新人最大的时间黑洞，别碰。

## 三、第 3 件：让它跳（约 2 小时）

把脚本补完整（这是第二版，最终版在 §四）：

```gdscript
extends CharacterBody2D

const SPEED: float = 147.0
const ACCEL: float = 1400.0
const FRICTION: float = 1800.0

const GRAVITY: float = 368.0        # 11.5 m/s² × 32
const JUMP_VELOCITY: float = -230.0 # 7.2 m/s × 32，负数=向上
const JUMP_CUT: float = 0.45        # 上升中松手，竖直速度乘这个
const COYOTE_TIME: float = 0.10     # 离开平台后还能跳的宽限
const JUMP_BUFFER: float = 0.12     # 落地前提前按跳，落地瞬间自动跳

var _coyote: float = 0.0
var _buffer: float = 0.0

func _physics_process(delta: float) -> void:
    # 1. 重力
    if not is_on_floor():
        velocity.y += GRAVITY * delta

    # 2. 计时器
    _coyote = COYOTE_TIME if is_on_floor() else maxf(_coyote - delta, 0.0)
    _buffer = JUMP_BUFFER if Input.is_action_just_pressed("jump") else maxf(_buffer - delta, 0.0)

    # 3. 起跳
    if _buffer > 0.0 and _coyote > 0.0:
        velocity.y = JUMP_VELOCITY
        _buffer = 0.0
        _coyote = 0.0

    # 4. 可变跳高
    if Input.is_action_just_released("jump") and velocity.y < 0.0:
        velocity.y *= JUMP_CUT

    # 5. 左右
    var dir := Input.get_axis("move_left", "move_right")
    if dir != 0.0:
        velocity.x = move_toward(velocity.x, dir * SPEED, ACCEL * delta)
    else:
        velocity.x = move_toward(velocity.x, 0.0, FRICTION * delta)

    move_and_slide()
```

**四段代码分别解决什么**（这段是明天最值钱的知识，慢点看）：

| 变量 | 解决什么毛病 |
| --- | --- |
| `JUMP_CUT` | 轻点空格小跳、按住大跳。没有它，跳的高度是固定的，平台跳跃的精度全靠运气 |
| `COYOTE_TIME` | 人已经跑出平台边缘了，但"心里觉得自己还在上面"。给 0.1 秒宽限，玩家会觉得"这游戏很跟手" |
| `JUMP_BUFFER` | 落地前 0.12 秒内按了跳，落地瞬间自动起跳。没有它，玩家会疯狂抱怨"我明明按了" |
| `GRAVITY` 单独调 | 觉得跳得矮/飘，**只调重力这一个数**，别去动初速——初速还决定了下落总时长 |

## 五、明天要学的 5 个东西

按重要性排的，前两个必须真懂，后三个做的时候顺手就懂了。

### 1. `CharacterBody2D` 和 `move_and_slide()` —— 横版角色专用车身

一句话：`CharacterBody2D`（角色车身）是一个"我按速度走，你负责别让我穿墙"的节点；`move_and_slide()`（移动并滑行）是它的核心方法，你给 `velocity`（速度，单位是像素/秒），它负责移动、撞停、沿坡滑。

- 为什么用它：自己写移动+碰撞，一个坡道能卡你两天。
- 5 分钟验证：把 `velocity` 打印出来看，撞墙后 x 变成 0 了 —— 说明引擎帮你处理了。

### 2. 物理帧（`_physics_process`）和 `delta`

一句话：`delta`（帧间隔，单位秒）是"上一次到现在过了多久"；`_physics_process`（物理帧回调）固定每秒 60 次，`_process`（渲染帧回调）跟着显示器刷新率乱跑。

- 为什么重要：所有乘法都要 `× delta`，否则快电脑上跑得快、慢电脑上跑得慢。你是联机游戏，这个不对，五台机器永远不同步。
- 5 分钟验证：在 `_physics_process` 里 `print(delta)`，跑起来应该稳定输出 0.0166。

### 3. 节点（Node）与场景（Scene）与实例化

一句话：节点是积木块，场景是"一堆积木的存档"，实例化（instantiate）是把这个存档复制一份放进当前场景。

- 为什么重要：整个技术框架的分层（地图、实体、组件）本质上就是"哪些做成场景、哪些做成节点"。
- 5 分钟验证：把 `测试关.tscn` 在 `World` 下拖三次，跑起来看到三块地板 —— 一个文件，三个实例。

### 4. 输入映射（Input Map）与动作名

一句话：把按键绑成"动作名"，代码只认动作名。

- 为什么重要：W5 加手柄、以后做改键界面，都靠它。
- 5 分钟验证：把 `jump` 的键从空格改成 J，代码不动，J 就能跳。

### 5. 加速度 vs 直接设速度

一句话：直接设速度 = 瞬间满速 = 塑料感；用加速度靠近目标速度 = 有重量 = 手感。

- 为什么重要：你这个游戏的全部卖点是"背上的重量"，而重量感的第一来源就是加减速，不是美术。
- 5 分钟验证：把 `ACCEL` 改成 99999 再跑一次，感受一下"瞬移"——然后改回来。
